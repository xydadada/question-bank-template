# 已知限制

这里记录模板会主动停止并保留资料的边界。

- 当前 `state.db` 仍以内容 SHA-256 作为旧版文件主键。两个仍存在、路径不同但
  字节完全相同的源文件目前共用旧版主键。程序会停止该资料组并要求只保留一份，
  由此保证批次、Markdown 和删除状态保持隔离。
- 所选云端 MinerU、MiMo、真实 WeKnora 和 ChatGPT Workspace 需要下载者自己的账号、
  密钥和内容。本地模型首次使用也需要下载权重。CI 验证本地逻辑和失败边界；
  真实端到端确认需要一份可丢弃样本。
- 本地 MinerU、Ollama 和模型权重由各自上游运行时管理。硬件、驱动和模型许可
  存在差异，目录中的体积说明只用于选型，首次真实运行仍需完成冒烟确认。
- 永久删除使用摘要、目录范围、显式确认和审计记录保护，但文件系统删除与
  SQLite 提交无法组成真正的跨系统原子事务。异常断电后，程序只会根据已提交
  的删除意图和哈希一致的保留 Markdown 收敛审计；无法确认的记录会明确保留为
  失败状态。请保留程序生成的审计记录。
- WeKnora v0.7.1 上游 Compose 为多个服务固定了 `container_name`。模板会为
  每个克隆生成稳定且不同的 Compose 项目名，防止停止脚本误认领其他克隆；
  同一 Docker daemon 上启动第二份 WeKnora 时，上游固定容器名会触发明确的启动错误，
  第一份实例的数据仍保持隔离。
- WeKnora 已发布 v0.7.2，但它包含约 200 个提交，并改动 CLI、MCP、分块、检索和
  Compose。模板固定在已完成兼容性审查的 v0.7.1。升级需要重新核对 CLI JSON 契约、
  三层检索、MCP 工具面和停止脚本，并同步更新版本与验证记录。

若这些边界影响使用，请提交可复现的最小样本，并保持安全检查启用。
